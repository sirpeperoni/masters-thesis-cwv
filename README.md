# Прогнозирование регрессий Core Web Vitals по фронтенд-коммитам

Код и данные магистерской диссертации **«Система прогнозирования регрессий производительности
фронтенд-коммитов по метрикам Core Web Vitals методами машинного обучения»**

Коммит во фронтенд-приложении может незаметно ухудшить скорость загрузки (LCP), отзывчивость (INP)
или стабильность вёрстки (CLS). Измерять каждый коммит дорого: лабораторные замеры нестабильны и
требуют многократных прогонов, а регрессии вносит лишь 1–7 % коммитов. Работа проверяет, можно ли
**по самому изменению кода** оценить вероятность регрессии и измерять в первую очередь рискованные
коммиты.

В репозитории:

- **стенд измерений** — собирает каждую версию приложения из истории git и измеряет Core Web Vitals
  в Lighthouse парами «база → коммит» с чередованием и статистической проверкой;
- **набор данных «коммит → изменение Core Web Vitals»** по четырём открытым проектам
  (более 1200 пар версий) и набор искусственных регрессий известной силы;
- **модели машинного обучения**, прогнозирующие регрессию по признакам изменения кода, и результаты
  их сравнения со случайным выбором и практическими эвристиками.

## Данные

### Модальности

| Модальность | Папка                | Формат                | Что содержит                                                                                                   | Объём        |
| ----------- | -------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------- | ------------ |
| Замеры      | `data/measurements/` | JSON, файл на пару    | Все прогоны Lighthouse для базы и коммита: метрики загрузки и сценария, элемент LCP, размеры сборки, окружение | ~1600 файлов |
| Таблицы     | `data/tables/`       | CSV, строка на пару   | Разметка: медианы, разности, p- и q-значения, метка по каждой метрике; 115 признаков изменения кода            | 10 файлов    |

(и `base_sha` / `base` — версией, с которой коммит сравнивается).

### Как получена разметка

1. **База** — предыдущая успешно собранная версия, **коммит** — текущая. Обе собираются из git
   командами проекта и раздаются одним и тем же статическим сервером.
2. Версии измеряются **вперемешку** (A B B A …): 5 пар прогонов, при подозрении на изменение —
   ещё 10. Каждый прогон — свежий профиль Chrome.
3. **Регрессия** по метрике — если ухудшение статистически значимо (критерий Манна – Уитни,
   поправка Бенджамини – Хохберга, q < 0,05) **и** не меньше порога практической значимости:
   LCP ≥ max(50 мс, 5 %), INP ≥ max(20 мс, 10 %), TBT ≥ max(30 мс, 10 %), CLS ≥ 0,01.
   Итоговая метка `label = regression` — регрессия хотя бы по одной из LCP, INP, TBT, CLS.
4. Доля ложных срабатываний проверяется **A/A-сравнениями** одинакового кода (68 сравнений,
   1 ложная метка), чувствительность — **мутантами**: в реальные коммиты внедряются регрессии
   заданной силы (длинная задача, медленный обработчик ввода, сдвиг вёрстки, блокирующий скрипт,
   раздутый бандл).

Подробности и обоснования — в [docs/concepts.md](docs/concepts.md).

### Поля данных

**`data/tables/labels/<проект>.labels.csv`** — строка на пару:

| Поле                      | Значение                                                  |
| ------------------------- | --------------------------------------------------------- |
| `sha`, `base_sha`, `date` | коммит, база, дата коммита                                |
| `status`                  | `ok` — измерено; `identical_build` — сборки совпали       |
| `aa`, `self_aa`           | контрольное A/A (одинаковые сборки / сборка сама с собой) |
| `extended`                | серия была расширена с 5 до 15 пар                        |
| `mutation`                | для мутантов: оператор и сила (`long_task-200`)           |
| `js_gzip`                 | размер JavaScript сборки после gzip, байт                 |
| `label`                   | итоговая метка: `regression` / `improvement` / `none`     |
| `<m>_base`, `<m>_head`    | медианы метрики у базы и коммита                          |
| `<m>_delta`, `<m>_rel`    | разность медиан и относительная разность                  |
| `<m>_p`, `<m>_q`          | p-значение Манна – Уитни и q-значение после поправки      |
| `<m>_label`               | метка по метрике                                          |

Метрики `<m>`: `lcp` (LCP при загрузке, мс), `inp` (INP в сценарии, мс), `tbt` (TBT при загрузке, мс),
`tbtFlow` (TBT в сценарии, мс), `cls`, `lcpObs` (наблюдаемый LCP без моделирования сети —
дополнительная метка, в `label` не входит).

**`data/tables/features/<проект>.features.csv`** — признаки изменения «база → коммит» по группам
(префикс в имени столбца):

| Префикс | Группа                                       | Примеры                                                                                                                                                                                                                                                                    |
| ------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `k_`    | классические метрики JIT (Kamei и др.)       | файлы, строки +/−, подсистемы, энтропия, возраст, опыт автора                                                                                                                                                                                                              |
| `cat_`  | типы изменённых файлов                       | число файлов и строк: код, стили, HTML, изображения, шрифты, тесты, документация, конфигурация, package.json, lock-файлы                                                                                                                                                   |
| `dep_`  | зависимости                                  | добавленные, удалённые, обновлённые пакеты (в т. ч. смена мажорной версии), отдельно runtime и dev                                                                                                                                                                         |
| `pat_`  | шаблоны кода фронтенда (добавлено / удалено) | импорты (статические, динамические, lazy), эффекты и состояние, обработчики событий, таймеры, requestAnimationFrame, циклы, чтение размеров и запись в DOM, canvas, workers, async, шрифты, изображения и их размеры, подсказки загрузки, CSS-анимации и тяжёлые селекторы |
| `msg_`  | сообщение коммита                            | тип по Conventional Commits (feat, fix, perf, refactor, chore…), откат, бот, длина, слово «perf»                                                                                                                                                                           |
| `bnd_`  | размер сборки                                | изменение JS, CSS и всей сборки после gzip (абсолютное и относительное), число файлов                                                                                                                                                                                      |
| `y_`    | целевые переменные                           | метки и разности метрик из разметки                                                                                                                                                                                                                                        |

**`data/measurements/<вид>/<проект>/<sha>.json`** — полный результат пары:

| Поле                                         | Значение                                                                                       |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `status`, `error`                            | итог; при сбое — текст ошибки                                                                  |
| `base`                                       | `sha` и хеш сборки базы                                                                        |
| `runs[страница][i]`, `baseRuns[страница][i]` | прогоны коммита и базы в порядке выполнения                                                    |
| `…navigation`                                | метрики загрузки: `lcp`, `cls`, `tbt`, `fcp`, байты, фазы LCP `lcp_*`, наблюдаемые `observed*` |
| `…interaction`                               | метрики сценария: `inp`, `tbt`, `cls`                                                          |
| `…lcpElement`                                | элемент, по которому посчитан LCP (селектор, текст)                                            |
| `bundle`                                     | размеры сборки по типам файлов                                                                 |

Рядом могут лежать `<sha>.aa.json` — A/A «сборка сама с собой».

**`data/text/<проект>.diffs.jsonl`** — строка на пару: `sha`, `base`, `files` (изменённые файлы),
`added`, `removed` (добавленные и удалённые строки в файлах кода, стилей и HTML; тесты, lock-файлы,
изображения и документация не входят; не более 200 000 символов на поле).

## Аннотации

Полное описание — [docs/annotation-schema.md](docs/annotation-schema.md), содержимое папок —
[annotations/README.md](annotations/README.md).

Разметка ведётся в два слоя: **автоматический** (статистическая метка регрессии, выбросы в прогонах,
шаблоны кода в строках, категория LCP-элемента по правилам) и **ручной** (оценка по diff, причина
регрессии, проверка категории LCP-элемента). Уровни детализации:

| Модальность | Уровень 1 | Уровень 2 | Уровень 3 |
|---|---|---|---|
| Замеры | Пара «база → коммит» | Метрика | Прогон |
| Текст: изменение кода | Коммит | Файл (фрагмент) | Строка (шаблон кода) |
| Текст: страница | Страница | LCP-элемент | Атрибуты элемента |

| Модальность | Где лежит | Формат |
|---|---|---|
| Замеры | `data/tables/labels/` (уровни 1–2), `annotations/measurements/<проект>.runs.csv` (уровень 3) | CSV, связь по `sha` |
| Текст: изменение кода | `annotations/text-diff/pilot-phase1.*.csv`, `pilot-phase2.*.csv`, `pilot-patterns.auto.jsonl` | CSV и JSONL с привязкой к файлу и строке |
| Текст: страница | `annotations/text-page/lcp-elements*.csv` | CSV, связь по `element_id` |

**Пилотная ручная разметка** — 50 пар (25 регрессий и 25 пар без регрессии, порядок перемешан, метки
скрыты) — размечена аннотатором B (языковая модель Claude) и проверена по эталону: измеренной метке
регрессии. Для расширения разметки описана процедура перекрёстного аннотирования с каппой Коэна
(`python ml/annotation.py agree <A> <B>`); та же мера для пары «правила — ручная проверка» категорий
LCP-элемента даёт κ = 0,40. Качество автоматической разметки проверено A/A-сравнениями
(68 сравнений, 1 ложная метка) и искусственными регрессиями.

Первые наблюдения: LCP-элементом в лаборатории только в 45 % прогонов оказывается основное содержимое
страницы — в остальных это промо-плашки, баннеры, подсказки и логотип; аннотатор B по одному diff
угадал 14 из 25 регрессий, отметив 16 пар из 50.

### Разметка текста описаний изменений

Сообщения коммитов и описания pull request'ов (23 документа от полустраницы до страницы, 5854 токена)

связаны с Wikidata. Разметка выгружена в WebAnno TSV 3.3 для INCEpTION (`annotations/text-desc/webanno/`).

## Код: установка и запуск

**Требования:** Node.js 22, Google Chrome, Python 3.11+ с `pandas`, `scikit-learn`, `scipy`,
`lightgbm`; для сборки проектов — git и corepack (pnpm/yarn).

```bash
npm ci --prefix bench
pip install pandas scikit-learn scipy lightgbm
```

| Команда                                                  | Что делает                                                                  |
| -------------------------------------------------------- | --------------------------------------------------------------------------- |
| `npm run trial -- --repo <проект> [--measure] [--aa 10]` | проба нового проекта: сборка трёх точек истории, пробный замер, оценка шума |
| `npm run bench -- --repo <проект> [--every 5]`           | сбор: сборка коммитов и парные замеры → `data/<проект>/`                    |
| `npm run bench -- --repo <проект> --mutants`             | искусственные регрессии → `data/<проект>-mutants/`                          |
| `npm run dashboard`                                      | панель наблюдения за сбором: http://localhost:4173                          |
| `npm run label -- --repo <проект>`                       | статистическая разметка → `<проект>.labels.csv`                             |
| `npm run sensitivity -- --repo <проект>`                 | кривая чувствительности по мутантам                                         |
| `npm run rq1`                                            | шум измерений и A/A-контроль                                                |
| `npm run features -- --repo <проект>`                    | признаки и текст изменений → `.features.csv`, `.diffs.jsonl`                |
| `npm run models -- --repo a --repo b … [--cross]`        | модели; `--cross` — обучение на одних проектах, проверка на другом          |

Стенд работает с рабочей раскладкой `data/<проект>/<sha>.json`, `data/<проект>.labels.csv` и т. д.;
в этом репозитории те же файлы разложены по модальностям (см. [структуру](#структура-репозитория)).
Новый проект подключается файлом конфигурации в `bench/repos/` — см. [bench/README.md](bench/README.md).

## Основные результаты

- **Методика измерения:** 68 контрольных A/A-сравнений одинакового кода — 1 ложная метка.
  По мутантам стенд находит сдвиг вёрстки от 40 px и медленный обработчик ввода от 25–50 мс;
  длинную задачу при загрузке в excalidraw — от 50 мс, а в mermaid её видит только наблюдаемый LCP:
  задача выполняется до первой отрисовки, и TBT её не учитывает (`results/sensitivity-*.json`,
  `results/rq1-noise.json`).
- **Прогноз на четырёх проектах** (1202 пары, 25 регрессий, обучение на прошлом — проверка на
  будущем): случайный лес находит 68 % регрессий среди 20 % самых рискованных коммитов против
  18 % у случайного выбора и 45 % у эвристики «вырос бандл».
- **Перенос на незнакомый проект:** модель, обученная на трёх проектах, на четвёртом находит
  55–100 % регрессий в тех же 20 % коммитов (`results/cross-*.json`).

Результаты предварительные: регрессий в каждом проекте единицы. 95 % доверительные интервалы
(стратифицированный бутстрэп) печатает `npm run models` и сохраняет в поле `_bootstrap` результатов.
