# cwv-risk — оценка риска регрессии Core Web Vitals

Ядро и консольная утилита «системы» диссертации (задачи е–ж введения): по изменению кода — коммиту или ветке
pull request — оценивает, насколько вероятно, что оно ухудшит LCP, INP, CLS или TBT, и советует, нужно ли
измерять его на стенде. Сборка и замеры для оценки не нужны.

## Как работает

1. **Признаки изменения** `merge-base(base, head) → head` — тот же код, что в экспериментах (`ml/features.py`):
   размер и разброс, что затронуто (код, стили, изображения, шрифты, конфиги), зависимости package.json,
   фронтенд-паттерны в добавленных и удалённых строках, сообщение коммита.
2. **Шкала проекта.** Признаки переводятся в перцентили относительно последних N коммитов основной ветки
   (по умолчанию 300; признаки истории кешируются в `<репозиторий>/.cwv-risk/history.csv`): модель оценивает,
   насколько изменение необычно для *этого* проекта, — так она переносится на проекты, которых не видела.
3. **Модель** — случайный лес на перцентилях (`models/forest-v1.joblib`), обучен на 4 полностью размеченных
   проектах (1329 изменений, 39 регрессий). Это модель, проверенная на 11 новых проектах (docs/results.md).
4. **Уровень риска** — по месту изменения среди истории проекта, с долей регрессий, наблюдавшейся на этом
   уровне в проверке на 11 проектах:

   | Уровень | Место среди истории | Регрессий в проверке | Рекомендация |
   |---|---|---|---|
   | высокий | верхние 5 % | 8,6 % (25 из 291) | измерить на стенде до слияния |
   | повышенный | 5–20 % | 2,8 % (24 из 869) | измерить, если есть время на замеры |
   | низкий | ниже 20 % | 0,7 % (2 из 279) | замеры можно пропустить |

5. **Объяснение** — признаки, по которым изменение необычно велико для проекта (перцентиль ≥ 80 %), по убыванию
   «важность в модели × необычность».

## Использование

Из папки `system/` (Python — `E:\Anaconda\python.exe`; зависимости — pandas, numpy, scikit-learn, joblib, typer):

```
python -m cwv_risk train                                       # обучить модель → models/forest-v1.joblib
python -m cwv_risk score --repo <путь> --base origin/main --head HEAD
python -m cwv_risk score --repo <путь> --base origin/main --head HEAD --format markdown   # для комментария в PR
python -m cwv_risk score ... --format json                     # для веб-панели и других программ
python -m cwv_risk score ... --fail-on high                    # код возврата 1 при высоком риске (проверка в CI)
```

Опции: `--history N` — длина шкалы; `--path src --path package.json` — учитывать в истории только фронтенд.
Первый запуск на проекте считает признаки истории (~2 мин на 200 коммитов), повторные — секунды.

## Проверка

- Коммит bentopdf f30a084f (27.12.2025; включил загрузку 71 МБ WebAssembly на главной, TBT +21 с) —
  **высокий риск, верхние 3 %** истории проекта.
- Прогон по 102 измеренным коммитам bentopdf (шкала — история до каждого коммита): высокий — 22 коммита,
  4 регрессии; повышенный — 53, 4; низкий — 27, 0. Все 8 регрессий — в высоком или повышенном уровне.
  (Измерены в основном коммиты, отобранные моделью, поэтому это проверка согласованности утилиты с моделью
  эксперимента, а не новая оценка качества.)
