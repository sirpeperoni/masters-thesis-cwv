# cwv-bench

Сбор датасета «коммит → изменение Core Web Vitals» для frontend-репозиториев.

Команды работают и из корня `E:\diplom`, и из `bench`:

```
npm run bench -- --repo excalidraw [--pairs 5] [--extra 10] [--aa-every 5] [--self-aa-every 15]
                 [--limit N] [--every K] [--sha <sha>] [--retry-failed] [--force]
npm run dashboard                      # http://localhost:4173
npm run label -- --repo excalidraw     # разметка → data/excalidraw.labels.csv
npm run noise -- --repo excalidraw-v1-sequential   # анализ шума (данные старой схемы)
```

## Методика

Каждый коммит сравнивается с **базой** — последней успешно собранной версией перед ним
(обычно предыдущий коммит first-parent истории).

1. `git checkout` → install (только если изменился хеш lock-файлов) → build.
   Сборка без source maps кешируется в `work/builds/<repo>/<sha>`, поэтому сборка коммита
   сразу служит базой для следующего — каждый коммит собирается один раз.
2. **Побайтно одинаковая сборка** (sha256 путей и содержимого) → статус `identical_build`,
   замеров нет: изменений производительности нет по построению.
   Каждое N-е такое сравнение (`--aa-every`) всё же измеряется как **контрольное A/A** —
   это эмпирическая оценка доли ложных срабатываний.
3. **Чередование A/B**: база (A) и коммит (B) измеряются вперемешку, AB BA AB BA…,
   каждый прогон — новый профиль Chrome (рабочий процесс Node — свой на каждый коммит). Дрейф среды
   (фоновая нагрузка, температура) действует на обе версии одинаково.
4. **Адаптивное число прогонов**: `--pairs` пар для всех; если хоть одна метрика подозрительна
   (p < 0.1 **и** |Δ| ≥ половины порога), добавляется ещё `--extra` пар.
   В ранних файлах (без поля `method`) правило было «или» — расширялся 31% коммитов, почти как от чистого шума;
   правило записывается в каждый результат (`method.extendRule`).
5. **A/A «сборка сама с собой»**: каждый `--self-aa-every`-й измеренный коммит дополнительно
   сравнивается сам с собой (`<sha>.aa.json`) — одинаковые сборки соседних коммитов редки (~2%).
6. **Сбой install/build → вторая попытка с нуля** (`git clean -fdx` вместе с node_modules):
   переиспользуемые node_modules иногда ломаются после смены lock-файла.

Прогон Lighthouse user flow:
- **navigation**: LCP, CLS, TBT, FCP + наблюдаемые (observed*) значения, элемент LCP (`lcpElement`)
  и фазы LCP (`lcp_timeToFirstByte`, `lcp_resourceLoadDelay`, `lcp_resourceLoadDuration`, `lcp_elementRenderDelay`);
- **timespan** по сценарию взаимодействий из конфига репозитория: INP, TBT, CLS.

## Разметка (`label.ts`)

Метка ставится по каждой метрике, если выполнены **оба** условия:

- q-value Бенджамини–Хохберга < 0.05 (тест Манна–Уитни; поправка отдельно по каждой
  метрике по всем сравнениям репозитория);
- |Δ медиан| ≥ практического порога:

| Метрика | Порог |
|---|---|
| LCP | max(50 мс, 5%) |
| INP | max(20 мс, 10%) |
| TBT (загрузка / сценарий) | max(30 мс, 10%) |
| CLS | 0.01 |
| LCP obs (наблюдаемый) | max(50 мс, 5%) — **дополнительная** метка, не входит в итоговую |

Пороги — `TARGETS` в `src/stats.ts`. Относительная часть нужна тяжёлым приложениям: у mermaid-live-editor
A/A дал MDE TBT ≈ 376 мс, и абсолютные 30 мс там превышаются одним шумом. Для excalidraw смена
правила (было: LCP min(50 мс, 5%), остальные только abs) не изменила ни одной метки.

## Настройки измерений

Desktop-экран 1350×940, CPU ×4, RTT 40 мс, 10 Мбит/с, язык браузера en-US
(до 29.09.2026 — язык системы: excalidraw измерен в ru-RU). Навигация — `simulate`
(Lantern), timespan — `devtools` (Lantern не поддерживает timespan).
Настройки пишутся в каждый результат (`env.settings`).

## Файлы

- `data/<repo>/<sha>.json` — результат (схема 2: `runs` коммита, `baseRuns` базы, `base`, `distHash`);
- `data/<repo>.labels.csv` — разметка;
- `data/excalidraw-v1-sequential/` — первые замеры старой (последовательной) методики;
- `work/status/<repo>.json` — статус текущего запуска для панели;
- `work/logs/<repo>/` — логи неудачных install/build.

## Новый репозиторий

Добавить `repos/<name>.ts`, реализующий `RepoConfig` (`src/types.ts`)
(пример с yarn→pnpm и SvelteKit — `repos/mermaid-live-editor.ts`):
команды install/build, папку сборки, страницы и сценарии взаимодействий.

## Искусственные регрессии (`--mutants`)

```
npm run bench -- --repo excalidraw --mutants [--mutant-commits 6] [--ops long_task --ops slow_input]
```

Берёт K уже успешно измеренных коммитов (равномерно по истории) и для каждого — все мутанты
из `src/mutations.ts`: антипаттерн заданной силы, внедрённый в коммит перед сборкой.
База — та же, что у коммита в основном датасете. Результат — `data/<repo>-mutants/<sha>__<мутант>.json`
(поле `mutation`), разметка — `npm run label -- --repo <repo>-mutants`.

| Оператор | Куда | Метрика | Уровни |
|---|---|---|---|
| `blocking_script` | синхронный скрипт в `<head>` | LCP | 25/50/100/200 мс |
| `long_task` | задача при старте | TBT | 50/100/200/400 мс |
| `slow_input` | обработчик pointerdown/keydown | INP | 10/25/50/100 мс |
| `layout_shift` | блок в начало страницы через 300 мс | CLS | 10/40/120/300 px |
| `bundle_bloat` | плохо сжимаемая строка в точке входа | байты, LCP | 50/200/800 КБ |

Точки внедрения — `mutation: { html?, entry }` в конфиге репозитория (без `html` — например, у VitePress —
HTML-мутанты пропускаются). Модульные вставки выполняются только в браузере (`typeof window`):
у SSG точка входа исполняется и при сборке в Node. Запускать только когда
основной сбор этого репозитория не идёт (общая рабочая копия).

## Внешние запросы (`blockedUrlPatterns`)

Время ответа внешних серверов зависит от интернета, а не от коммита. При прогреве стенд записывает
внешние домены страницы в результат (`externalHosts.external` / `.blocked`) и печатает незаблокированные
в строке консоли. Шаблоны блокировки — `blockedUrlPatterns` в конфиге (`*` — любые символы):

```ts
blockedUrlPatterns: ['*simpleanalyticscdn.com*', '*googletagmanager.com*'],
```

**Блокировать только аналитику, рекламу, виджеты.** Функциональные ресурсы (шрифты, картинки
с CDN приложения) блокировать нельзя: у excalidraw блокировка его CDN подняла LCP с ~1,2 до 3,4 с.
Проверка после добавления шаблона — метрики пары прогонов с блокировкой и без должны совпадать в пределах шума.

У excalidraw блокировки нет намеренно: так собран весь его датасет (внешние запросы — CDN со шрифтами
и аналитика — действуют на обе стороны пары одинаково). Список пишется в каждый результат (`env.blockedUrlPatterns`).

## Ловушки при подключении репозитория

- **Файлы, которые создаёт `postinstall`** (например, `.svelte-kit/` от `svelte-kit sync`), при
  переключении коммита удаляются (`git clean` чистит всё игнорируемое, кроме `node_modules`),
  а install пропускается, если lock-файл не менялся. Такие шаги нужно повторить в `build`.
- **Скрипт сборки сам вызывает `pnpm`/`yarn`** — они есть только через corepack; добавить
  `bench/shims` в PATH конфига (пример — `repos/mermaid-live-editor.ts`).
- **Смена менеджера пакетов в истории** (yarn → pnpm): старые node_modules мешают новому;
  run.ts справится повторной попыткой с нуля, в пробе — флаг `--clean`.
- Проверять всё это пробой: `npm run trial -- --repo <name> [--measure] [--aa 10]` —
  без `--sha` три точки (старая, средняя, новая); `--aa N` — шум на этом приложении.
