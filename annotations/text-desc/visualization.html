## :straight_ruler: Design Decisions
подзаголовок
### Dependency update
список изменений
- **`@mermaid-js/layout-elk` removed.** Mermaid 12 bundles ELK and registers it automatically (it is also the new default layout). Keeping the package would ship a second copy of the layout engine and its `1.0.0` release still declares a `mermaid@^11` peer range. `src/lib/util/mermaid.ts` now only registers tidy-tree, which is not bundled.
- **Peer-dependency warnings.** `@mermaid-js/layout-tidy-tree@1.0.0` and `@mermaid-js/mermaid-zenuml@1.0.0` still declare `mermaid@^11` as a peer. pnpm reports this as a warning only; the upstream packages need their peer ranges bumped.
- The app does not use the removed `defaultRenderer` option or the removed layout-internal exports, and `standardizeDiagramType` already normalises the diagram ids that changed.
подзаголовок
### Theme follows the diagram type
описание
Mermaid 12 gives ten config sections their own default theme (`redux-color` with the `neo` look for flowchart, swimlane, agentflow, sequence, class, state, ER, requirement, use case and Venn); everything else uses the global `default`. Pinning `"theme": "default"` in every config, as the editor used to, opted every user out of that.
список изменений
- **`syncManagedTheme` (state module).** After every validation, and whenever the site switches light/dark, the theme is set to the current diagram type's default — `getDefaultTheme(diagramType)` reads the config section's `theme` from `mermaid.mermaidAPI.defaultConfig`, falling back to the global one — or, in dark mode, `darkVariantOf` it: redux themes get their `-dark` variant (`redux-color` → `redux-dark-color`), anything else becomes `dark`. It converges after one update because the next validation finds the theme already in place.
- **Only editor-set themes are replaced.** `isManagedTheme` accepts a missing theme, the global default, every section default and their dark variants. A theme the user typed into the config (`forest`, `neo`, `base`, …) is never touched, in either mode or when the diagram type changes.

**Business value**

    - it was additionally adjusted to fit our needs
       - removed non-CJK codepoints
       - reduced any Hangul side-bearings to 40%
       - centered in width of inproperly centered CJK codepoints (mainly Hangul Jamo, but also others)
     - it was manually split into multiple woff2 font faces for lazy-loading with https://chinese-font.netlify.app/online-split

1. Added support for multicodepoint Emojis wrapping (in other words, emojis won't be broken apart during wrapping anymore)
1. Added keyboard shortcut for SVG export (`ctrl+shift+c` on all the platforms) with a toast once completed (similar to PNG).
1. Mitigated subsequent FOUT by fixing local caching for fonts hosted on our CDN (previously cross-origin requests for fonts were not being cached by the service-worker).

проверка
**Technical parts**
[изображение]
https://link.excalidraw.com/readonly/MbbnWPSWXgadXdtmzgeO
список изменений
1. Improved overall SVG export to process `FontFace`s concurrently (with or without workers, fetching and processing max 3 at a time) with some additional perf. optimisations.
1. Offloaded SVG export in `excalidraw-app` to shortlived `Web Workers` (re-used or terminated after 500ms of inactivity) due to performance issues on the main thread (i.e. just Xiaolai consists of about 250 font faces, which would make the editor unresponsive for a few seconds).

#### Patch Changes
заметки к релизу
- Reject `pnpm-lock.yaml` entries whose remote tarball `resolution:` block is missing the `integrity` field. Previously the worker that extracts a downloaded tarball skipped hash verification when no integrity was supplied and minted a fresh one from the unverified bytes, so an attacker who could both alter the lockfile (e.g. via a pull request that strips `integrity:`) and serve modified content at the referenced tarball URL could install a tampered package without any error — including under `--frozen-lockfile`. pnpm now fails closed at lockfile-read time with `ERR_PNPM_MISSING_TARBALL_INTEGRITY`. Git-hosted tarballs (`gitHosted: true` or a URL on codeload.github.com / bitbucket.org / gitlab.com) and `file:` tarballs are exempt — the commit SHA in a git-host URL and the user-controlled local path already anchor the bytes.
